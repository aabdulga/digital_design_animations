4-to-2 Priority Encoder

An encoder does the reverse of a decoder: it reports which input line is active as a binary number. A priority encoder accepts any pattern of inputs and reports the highest-numbered active one; D3 wins over everything. The valid output V says whether any input is active at all.

Block view

What it does

Several request lines may be on at once. The encoder picks the highest-numbered active line, ignores the ones below it, and outputs that line's number in binary on Y1 Y0. V = 1 says "some line is active".

Why priority?

A plain encoder assumes exactly one input is 1; with two 1s its output is meaningless (D1 and D2 together would give 11). Priority makes every input pattern defined: lower inputs are ignored. Equations: Y1 = D3 + D2, Y0 = D3 + D2'·D1.

Why V is needed

Both "only D0 active" and "nothing active" put 00 on Y. The valid bit V = D3 + D2 + D1 + D0 tells them apart; when V = 0, Y is a don't-care.

Where it is used

Interrupt controllers use one to pick the most urgent pending request. Keyboard scanners use one to turn a pressed key line into a key code, even if several keys are held.
